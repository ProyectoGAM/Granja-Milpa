# Mapbox location for production units

## Objective

Replace manual latitude/longitude fields and the future-map notice in GAM production-unit create, edit, and detail screens with a Mapbox address and map flow. Persist a readable address with the existing numeric coordinates while keeping historic rows usable.

## Problem and rationale

GAM currently stores only `latitude` and `longitude`; users must type coordinates and cannot review a point on a map. Voltio supplies the reference pattern for Mapbox GL JS lifecycle, a reusable location picker, suggestion selection, draggable markers, and `[longitude, latitude]` ordering. GAM needs its own reverse address lookup and nullable address persistence because Voltio's create/edit flow does not provide those behaviors.

## Authorized scope and constraints

- Change only `GAM-Frontend` and `GAM-Backend` production-unit location behavior and its focused tests/migration.
- Do not modify Voltio or ProConnect.
- Reuse GAM's existing `environment.mapbox.accessToken`; never print, copy into tests, or log its value. Existing edits in all four frontend environment files predate this work and must be preserved.
- Keep the current `latitude` and `longitude` API fields and their order in persistence. Convert Mapbox `[longitude, latitude]` at the integration boundary.
- Use a nullable address column to preserve historic records. Do not backfill from Mapbox or add another location schema.
- Preserve geography, name, status, access rules, inactivation, poultry houses, and feed plants.
- No production data access or mutation, deployment, commit, or push. Local code and tests are authorized.
- The user explicitly authorized installing `mapbox-gl` from npm and updating/rebuilding only the frontend service; do not remove any PostgreSQL volumes.
- This continuation also authorizes removing the production-unit department/locality selectors, validating selected points as Uruguay, making the minimum catalog relationship change required for rural locations, and replacing the administrative delivery tracking map with Mapbox backed by real delivery data for the selected production unit.
- Do not add fictional delivery data or live movement. Preserve Leaflet while any other screen still uses it. No production access, deployment, commit, or push.
- No Engram memory tools are available in this runtime; the repository task file is the recovery record and the mirror remains pending/unavailable.

## Acceptance criteria

- Create requires a confirmed valid point and a non-empty bounded address; coordinates remain numeric API fields and are validated for finite values and geographic ranges in frontend and backend.
- Edit loads the persisted address and point; unchanged historic coordinates without an address remain editable and saveable. Changing a point requires a valid address label.
- Edit submits location, ordinary fields, and the chosen status as one atomic save; a failed save cannot persist a partial location or status change. Existing explicit status-transition rules and actions remain authoritative.
- Search prioritizes Uruguay and the selected department/locality when available, without restricting manual map selection. Suggestion, map click, and marker drag update the point coherently; stale search/reverse-geocode responses cannot overwrite newer input.
- Manual address correction is an explicit confirmation for the already selected pin. Editing address text cannot silently retain mismatched coordinates.
- Map initialization, load/click timing, resize, marker/listener teardown, pending requests, Angular reactivity, touch use, and useful error states are handled.
- Detail displays the address and a read-only map for valid coordinates. Invalid historic coordinates show “Ubicación no disponible” without drawing a fallback point.
- Existing production-unit state, geography, access and facilities behavior remains intact.
- Focused tests cover create/edit/detail API contract and validation plus suggestion, click, drag, stale requests, and an old row without an address, within the existing test infrastructure.
- Create/edit no longer ask the operator for department/locality. A locality is resolved only from verified Mapbox administrative context and GAM's real catalogs; rural points that do not resolve unambiguously can be stored with nullable `locality_id`, preserving all existing relationships and rows.
- Frontend selection calls GAM's point-validation endpoint, and create/update writes repeat the same official national-boundary polygon check; map bounds and geocoder text are not treated as validation. Rejected suggestions/clicks/drags preserve the prior valid point. Search is scoped to `UY` and map view is framed/limited around Uruguay.
- Delivery tracking uses the selected admin production unit and actual current/history delivery resources. Refresh re-queries both. Map markers come only from persisted, finite in-range production-unit, stop, or vehicle location coordinates; it draws no fabricated routes or motion. Empty/error/loading and missing-location states are visible.
- Delivery list selection and map focus remain synchronized after refresh and unit changes; the Mapbox map and listeners are cleaned up on navigation. Leaflet remains installed while the driver screen uses it.
